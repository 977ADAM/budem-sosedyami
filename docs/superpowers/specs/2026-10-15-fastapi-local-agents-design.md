# Локальные ИИ-соседи на FastAPI и DeepSeek

## Цель

Добавить к демо локальный backend на FastAPI, где работают четыре ИИ-соседа, и разнести проект по `frontend/` и `backend/`. Интерфейс остаётся на SvelteKit, пользователь выбирает только готовые вопросы, а все персонажи и сведения о районах/ЖК остаются вымышленными и ограниченными данными текущего демо.

Успех: обе части запускаются локально отдельно; фронтенд общается с FastAPI, FastAPI обращается к DeepSeek, а при ошибке AI-запроса игра продолжает сценарий с существующими заготовленными ответами.

## Структура проекта

```text
project-root/
  frontend/        # текущий SvelteKit проект: src, static, package.json, Vite/Svelte config
  backend/
    app/
      main.py      # FastAPI приложение и POST /api/chat
      agents.py    # профили, вымышленные знания и инструкции агентов
    requirements.txt
    .env.example
  docs/
  .gitignore
  README.md        # команды запуска обеих частей
```

Существующие файлы SvelteKit переносятся в `frontend/`. Python-сервис остаётся независимым приложением. Новые внешние зависимости фронтенда не добавляются; backend использует FastAPI, Uvicorn, HTTPX и `python-dotenv` для чтения локального `.env`.

## Архитектура и поток запроса

Фронтенд запускается через Vite на `127.0.0.1:5173`. В dev-конфигурации `/api` проксируется на FastAPI по адресу `http://127.0.0.1:8000`, поэтому browser-запрос same-origin и отдельная CORS-конфигурация не нужна. Backend запускается через `uvicorn app.main:app --reload --port 8000` из `backend/`.

Фронтенд отправляет `POST /api/chat` с JSON:

```json
{
  "agent_id": "anton",
  "question_id": "work"
}
```

Backend проверяет `agent_id` и `question_id` по серверному реестру, собирает system prompt из профиля персонажа и добавляет серверную историю этого соседа и текст выбранного вопроса. Так endpoint принимает только существующие готовые вопросы, а клиент не управляет контекстом агента. Ответ имеет вид `{ "reply": "..." }`. `GET /api/dialogue/{agent_id}` возвращает успешные AI-ответы для отображения, `POST /api/dialogue/reset` очищает историю всех соседей. Неизвестный агент даёт 404; неизвестный вопрос — 422; отсутствующий ключ — 503; таймаут DeepSeek — 504; прочие ошибки upstream — 502. API-ключ хранится в `backend/.env` и никогда не отправляется в браузер.

DeepSeek Chat Completions вызывается по `https://api.deepseek.com/chat/completions`. Модель задаётся `DEEPSEEK_MODEL`, по умолчанию `deepseek-flash`; запрос нестриминговый. Источники: [документация Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) и [пример настройки DeepSeek API](https://api-docs.deepseek.com/guides/codex).

## Агенты и знания

`backend/app/agents.py` содержит реестр четырёх агентов: Антона, Марину, Павла и Веру. У каждого есть голос/роль, перечень разрешённых `question_id` и база вымышленных фактов, перенесённая из текущих данных демо: вступление, ответы на готовые темы, проект, особенности, цитата и подходящая планировка. System prompt запрещает представлять сведения вне профиля как факты и просит прямо обозначать отсутствие информации.

Фронтенд сохраняет текущие данные для отображения карты, профилей, вариантов вопросов, fallback-ответов и финального результата. Для быстрого прототипа серверный реестр повторяет только контекст, нужный модели; при переносе нужно сверить его с текущим `people` в `game-map-start.js`. Никаких реальных сведений и внешних баз знаний не добавлять.

## Поведение интерфейса

- Карта, четыре героя, готовые кнопки вопросов, цель из трёх совпадений, выбор соседа и экран результата сохраняются.
- Свободный текстовый ввод не добавляется.
- Backend хранит историю диалога в памяти процесса отдельно для каждого героя. В историю попадают только готовые вопросы и успешные ответы DeepSeek; fallback-ответы в неё не включаются.
- Фронтенд загружает ответы через API для отображения. Тонкий `agent-api.js` только отправляет запросы и читает ответ backend.
- Одновременно отправляется не более одного вопроса. Вопросная кнопка показывает ожидание/блокируется на время ответа.
- При успешном ответе backend сохраняет реплику и возвращает `reply`; фронтенд отображает результат.
- При backend/DeepSeek ошибке, отсутствии ключа, таймауте или невалидном ответе фронтенд показывает текущий статичный `q.answer`, сообщает о fallback и сохраняет проходимость игры.
- Если во время ответа пользователь сменил экран или собеседника, результат записывается исходному собеседнику и не вставляется в другой чат.

## Настройка и запуск

- Backend: `cd backend`, создать venv, установить `requirements.txt`, скопировать `.env.example` в `.env`, задать `DEEPSEEK_API_KEY`, при необходимости `DEEPSEEK_MODEL`, запустить Uvicorn с `--env-file .env` на порту 8000.
- Frontend: `cd frontend`, выполнить `npm ci`, затем `npm run dev`.
- Корневой `.gitignore` исключает `frontend/node_modules`, `frontend/.svelte-kit`, `frontend/dist`, `backend/.venv`, `backend/.env`, `__pycache__` и байткод Python. В репозитории остаётся безопасный `backend/.env.example`.
- Корневой README описывает запуск обоих процессов в двух терминалах и отмечает, что backend предназначен только для локальной демонстрации.

## Проверка и ограничения

После реализации вручную проверить health/доступность backend, успешный вызов при наличии ключа, понятный fallback без ключа и при ошибке DeepSeek, разделение историй и возможность пройти выбор/раскрытие результата. Выполнить production build фронтенда. Автоматические тесты в рамках быстрого прототипа не добавлять.

Backend доступен только локально и не предназначен для публикации. Истории живут в памяти backend-процесса, не записываются на диск и пропадают при перезапуске. LLM может ошибиться или выдумать детали несмотря на ограничения промпта. Фронтенд продолжает содержать статичные копии для показа и fallback, поэтому агентский контекст в Python нужно сверять с ними.

## Вне объёма

- Публичный deployment backend или frontend.
- Реальные данные ЖК, базы знаний, поиск/retrieval.
- Свободный ввод, tool calling, многошаговые автономные сценарии.
- Аккаунты, долговременное хранение истории, аналитика, лимитирование публичных пользователей.
