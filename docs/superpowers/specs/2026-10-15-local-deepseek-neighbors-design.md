# Superseded: локальные ИИ-соседи через Vite proxy

Эта версия заменена архитектурой FastAPI и каталогами `frontend/` + `backend/`. Актуальная спецификация: [2026-10-15-fastapi-local-agents-design.md](2026-10-15-fastapi-local-agents-design.md).

## Цель

Заменить статичные ответы четырёх соседей на ответы DeepSeek в локальной демонстрации игры «Будем соседями?». Зритель выбирает только готовые вопросы. Персонажи, биографии, ответы на вопросы, сведения о районах и жилых комплексах остаются вымышленными и опираются только на данные, уже заложенные в демо.

Успех прототипа: локальный запуск позволяет пройти текущий сценарий игры, получить контекстные ответы от выбранного соседа и завершить игру при доступном DeepSeek API; при недоступном API сценарий остаётся проходимым со статичными демо-ответами.

## Текущее устройство

- `src/lib/game-map-start.js` содержит данные четырёх персонажей, вопросы, заготовленные ответы, игровой стейт, рендеринг чата и обработчики событий.
- `src/routes/+page.svelte` содержит экран чата и контейнер готовых вопросов.
- `vite.config.js` запускает SvelteKit через Vite.
- `svelte.config.js` использует `adapter-static`; финальная статическая сборка не предоставляет серверных API-маршрутов.
- `src/app.css` оформляет весь интерфейс.

## Предлагаемое решение

Оставить существующий SvelteKit и статическую сборку. Во время локального `npm run dev` использовать Vite dev-server proxy для пересылки запросов от браузера к DeepSeek Chat Completions API. Прокси читает `DEEPSEEK_API_KEY` из локального окружения и добавляет заголовок авторизации на исходящий запрос. Браузер вызывает только локальный адрес `/api/deepseek/chat/completions`; ключ в клиентский код или production-сборку не передаётся.

Запрос использует официальный совместимый формат DeepSeek Chat Completions: `POST https://api.deepseek.com/chat/completions`, JSON с `model`, `messages` и обычным нестриминговым ответом. Модель задаётся через `DEEPSEEK_MODEL` и имеет значение по умолчанию `deepseek-flash`, чтобы её можно было поменять без правок UI. Источник: [документация Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) и [первый API-вызов](https://api-docs.deepseek.com/guides/codex).

## Поток разговора

1. Игрок выбирает одного из четырёх соседей и нажимает готовый вопрос.
2. Приложение добавляет этот вопрос к истории соответствующего соседа, помечает его ожидающим и временно блокирует повторную отправку вопроса/других вопросов до завершения запроса. Счётчик найденных совпадений продолжает учитывать выбранный вопрос, как сейчас.
3. Клиент формирует сообщения для модели: системная инструкция персонажа, приветствие и предыдущие пары «вопрос — ответ» этого соседа, затем новый вопрос. История раздельна для каждого соседа. Запросы выполняются без streaming.
4. Системная инструкция использует только поля персонажа, которые уже есть в объекте `people` (роль, вступление, вопросы/ответы, проект, особенности и цитата). Она задаёт тон персонажа, запрещает выдавать новые сведения о ЖК и районе за факты и просит прямо говорить, если нужной информации нет. Это снижает вероятность выдумок, но не гарантирует её полного отсутствия.
5. При успешном ответе текст сохраняется в локальном стейте рядом с выбранным вопросом и отображается в чате. При ошибке, таймауте или отсутствии ключа показывается соответствующий заготовленный `q.answer`; игровой прогресс сохраняется, а интерфейс сообщает, что показан демо-ответ.

## Изменения по файлам

- `vite.config.js`: настроить dev-only прокси, загрузку непубличных локальных переменных и заголовок `Authorization`. Прокси не добавляется в production-сборку.
- `.gitignore`: игнорировать `.env` и локальные варианты, сохранив возможность коммитить `.env.example` без секретов.
- `src/lib/game-map-start.js`: хранить ответы модели и состояние ожидания отдельно для каждого соседа; формировать сообщения; вызывать локальный endpoint; показывать AI-ответ либо заготовленный fallback; не отправлять ещё один вопрос, пока запрос активен.
- `README.md`: описать создание локального `.env.local` с `DEEPSEEK_API_KEY` и необязательным `DEEPSEEK_MODEL`, а также отметить, что AI-ответы работают только с Vite dev server.

Разметка `src/routes/+page.svelte` и `src/app.css` меняется только если существующих элементов недостаточно для состояния ожидания/ошибки. Сценарий с кнопками-вопросами сохраняется; поле свободного ввода не добавляется.

## Ошибки и ограничения

- Нет ключа или сеть недоступна: используется заготовленный ответ, игра продолжается.
- API отвечает ошибкой или неуспешным статусом: ответ не считается успешным; используется тот же fallback.
- Повторная отправка во время запроса блокируется, чтобы не создавать конкурирующие ответы и нарушенный порядок сообщений.
- История чата хранится только в памяти страницы и сбрасывается при перезагрузке/сбросе игры; серверного хранения нет.
- Это локальный прототип. При публикации статической сборки AI endpoint не существует, а прокси Vite недоступен. Публичное размещение потребует отдельной серверной архитектуры.
- Локальный прокси защищает ключ от передачи в браузер и статический bundle. Любой пользователь с доступом к локальному компьютеру и файлу окружения может прочитать ключ.

## Проверка реализации

После реализации вручную проверить локальный сценарий с настроенным ключом: ответы каждого соседа учитывают своего персонажа и историю, вопросы продолжают считаться совпадениями, выбор и раскрытие результата работают. Отдельно проверить отсутствие ключа/ошибку API и убедиться, что появляется fallback и игра завершается. Проверить production build на отсутствие API-ключа и работоспособность существующего статического демо. Автоматические тесты в рамках этого быстрого прототипа не добавлять.

## Вне объёма

- Свободный текстовый ввод.
- Внешние базы знаний, реальные сведения о ЖК, поиск или retrieval.
- Tool/function calling, автономные цепочки действий и координация нескольких моделей.
- Учётные записи, серверное хранение истории, аналитика, лимиты для публичных пользователей.
- Публикация AI endpoint в интернете.
